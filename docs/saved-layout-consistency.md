## 2. 여섯 개념을 분리한다

| 개념 | 의미 | 잘못된 추론 |
|---|---|---|
| 줄바꿈 입력 | TextAreaInput.lineBreak의 AutomaticLineBreak / SpecifiedLineBreak. 입력 제약 | specified이면 사용자 편집 결과·확인 필요라는 추론 |
| 결과 작성 경위 | 엔진이 생성한 결과인지, 사용자가 결과 배치를 편집했는지 | 엔진 생성 완료를 제작 승인으로 간주하거나 수동이면 검사 생략 |
| 검사·판정·사유 | 실제 결과에 어떤 검사를 어떤 조건으로 수행했고 무슨 판단을 했는지 | 검사 미수행을 통과로 바꾸거나 판정 사유를 확인으로 덮음 |
| 결과별 작업자 확인 | 특정 제품의 특정 불변 결과를 보고 채택했다는 기록 | 제품에 영구 confirmed bool을 붙이거나 결과 없이 확인만 보관 |
| 현재 입력과의 대응 | 실제 입력 내용/의존성과 실행 수명에서 현재로 채택된 연결 | ID·문구만 같으면 현재, 내용이 원복되면 과거 결과 자동 재승격 |
| 작업 파일 저장 판단 | 모든 제품의 현재 완료 결과·필요 검사·확인을 종합한 파생 판단 | 영역 하나의 성공/확인 또는 유효 구성 생성만으로 파일 전체 저장 허용 |

직접 지정 한 줄/여러 줄도 엔진이 크기·자폭·위치를 정상적으로 맞출 수 있다.
반대로 자동 입력의 결과도 사용자 편집을 거칠 수 있다. 결과 작성 경위와 입력 방식은 독립적이다.
사용자가 결과를 수정했다는 이유만으로 무조건 확인 필요/정상으로 판정하지 않는다.
수정한 실제 결과를 검사하고, 확인이 필요한 기준 이탈인지 판단한다.
입력 제약 자체를 바꾸는 명령과 결과 좌표/크기 편집은 구분한다. 직접 지정 줄을 위반한 결과를
결과 편집이라는 이유로 수락하지 않는다. 자동 입력의 산출 줄 재편집과 입력 방식 전환의 UI 의미는 후속 명령 계약에서 결정한다.

## 3. 결과가 의존하는 실제 입력

### 내용과 출처/표시를 분리한 투영을 추천한다

ProductDesignConfiguration에서 해당 제품의 유일한 적용 형상·영역 입력을 해석한다.
단순히 configuration 전체 또는 AppliedDesignGeometry 전체를 비교하면 label/source/비대상 제품까지 포함되므로
이를 배치 무효화 판단에 그대로 쓰지 않는다. 기존 적용 ID의 내용 불변 검사와 배치 입력 투영은 다른 책임이다.

| 정보 | 배치 근거로 포함할 것 | 제외/주의 |
|---|---|---|
| 형상 | 실제 외곽·관통 경계·영역/제외 경계와 좌표 문맥 | 원/사각 홀 등 특정 형상으로 대체하지 않음. label·공용 출처 자체는 제외 |
| 문구 | areaId 대응, sourceText 원문·자동/직접 방식·전체 지정 줄 조각 | trim·정규화·동일 문구 제품 병합 없음 |
| 글꼴/측정 | 실제 글꼴 자원/스타일·기능·사용한 측정 값 또는 해석 가능한 불변 측정 자료 | 글꼴 이름/버전/해시만으로 실제 내용 동등성 대체 불가 |
| 규칙·패턴 | 계산에 사용한 실제 결합값, 설정 의도 중 계산 의미, 적용 패턴 내용·결합 정책 | 최신 공용 기준 재조회/출처 버전만으로 대체하지 않음 |
| 제작 조건 | 글자 가공 커터 조건처럼 실제 계산/검사에 쓰는 부분 | 자재·두께·색상 전부를 자동 포함하지 않음. 실제 측정/대비/가공 제약에 영향을 주는 항목만 명시 |
| 자동 그룹 | 참여 productId+areaId와 실제 관련 입력·선택 정책·완전한 의존 범위 | 같은 적용 도안 공유를 같은 자동 그룹으로 간주하지 않음 |
| 계산 환경 | 실제 생성 엔진/알고리즘·탐색 설정·측정 계약과 계산에 쓰인 자료 | 현재 설치 환경을 저장 당시 환경으로 덮어쓰지 않음 |
| 수량·출력 | 문구 배치 근거에서 제외 | 복제 수·명판 밖 수량 표시·출력 순서 등은 출력 구성에서 관리 |
| 표시/관리/출처 | 단순 표시명·영역 label·공용 원본 위치·작성 설명은 제외 | label을 영역 역할/규칙 선택 키로 쓰지 않음. 문자열이 실제 문구로 출력되면 그 부분은 별도 입력 |

제작 방식 이름이 바뀌었어도 실제 계산 조건이 같으면 그 이유만으로 재계산하지 않는다.
인쇄 문구에 외곽 CNC 가공의 글자 커터 제약을 끼워 넣지 않는다.
어떤 제작 조건이 계산에 들어가는지 모르면 무조건 포함/무조건 제외하지 않고 지원 조건 결정을 남긴다.

단위와 저장 수치가 바뀌는 환산은 표현 변화다. 첫 비교는 임의 반올림/허용오차/물리적 동등성 추정을 하지 않는다.
좌표계·단위를 포함한 실제 값이 다르면 근거가 다르며 결과 좌표와 함께 명시 변환/새 결과 검토가 필요하다.

### 최소 공유 구조 — 전체 문서 복제 금지

추천 관계(저장 JSON 스키마가 아님):

```text
문서 내 불변 적용 내용/계산 자료 풀
  ↳ 제품별 입력 근거 → 영역 입력 + 실제 기하/조건 + 필요한 그룹 의존 → 불변 자료 참조
  ↳ 제품별 결과     → 입력 근거 참조 + 영역별 줄/배치 + 검사/판정
  ↳ 결과별 확인     → 정확한 제품/결과 참조
```

ID는 문서 안의 이름 공간에서 중복을 거부하고, 같은 ID는 같은 전체 내용을 가리켜야 한다.
참조를 따라 실제 내용까지 해석·검사할 수 있어야 한다. 파일 밖 공용 원본/현재 폰트 설치만 가리키지 않는다.
불변 기하·원문·측정/규칙 자료를 메모리에서 공유하고 저장 풀로 중복 제거할 수 있다.
각 결과에 다른 제품·수량·관리 정보까지 포함한 작업 파일 전체를 복제하지 않는다.
그룹 근거도 관련 참여 입력만 참조하며 결과↔다른 결과의 순환 참조를 만들지 않는다.

결과 근거와 현재 적용 참조의 ID가 달라도 실제 계산 내용이 같음을 증명한 메타데이터 변경은 재계산 원인이 아니다.
단, 같은 ID가 다른 내용인 손상은 내용이 비슷하다는 이유로 허용하지 않는다.
출처만 바꾸려 해도 현행 AppliedDesignGeometry의 동일 ID 내용 교체 금지는 유지한다.
새 적용 ID를 사용하되 배치 영향은 별도 내용 투영으로 판단한다. 명시적 연결 검증 없이 과거 결과를 자동 승계하지 않는다.

아직 없는 것: 전체 규칙/패턴 결합 타입·최초 제작 조건·측정 자원 스냅샷·탐색 설정·그룹 정책/검증기.
이를 Map, 불명확한 null, 빈 목록/가짜 기본값으로 채워 완전한 CalculationInput이라고 부르지 않는다.
정말 독립 계산인 경우에만 명시적 '그룹 의존 없음' 상태가 가능하다. 모르는 그룹을 없음으로 바꾸지 않는다.

## 4. 모델 책임·이름 후보

아래는 추천 책임과 필드 방향이다. 최초 지원 조건이 결정되지 않은 타입의 구현을 지금 요구하지 않는다.

| 책임/추천 후보 | 주요 내용/관계 | 다른 후보와 의미 |
|---|---|---|
| ProductLayoutInputBasis | productId, 기하/영역 입력, 실제 조건/자료 참조, 관련 그룹·계산 환경. 불변 실제 내용 | CalculationInputSnapshot은 캡처 경위가 드러나지만 무엇의 입력인지 넓음. LayoutInputId만으로 대체 불가 |
| ProductLayoutResult | 문서 내 resultId, productId, inputBasis 참조, 영역 결과 목록, 작성 경위, 검사·판정·사유 | SavedLayoutResult는 '저장됨'과 값 생성 혼동 가능. LayoutResult는 엔진 내부 결과와 구분 필요 |
| AreaLayoutResult | 결과 소유 범위의 areaId, 순서 있는 줄 배치·원문 대응, 영역 전체 검사 | AreaLayout은 간결하나 정의/계산 결과 구분이 덜 명확함 |
| LayoutLinePlacement | 줄 원문 대응, 기준 좌표, 실제 크기/자폭·글꼴, 필요한 방향/텍스트 배치 계약 | LineResult는 검사 결과와 혼동. GlyphLayout은 실제 글리프 표현을 결정하기 전 과도함 |
| LayoutInspection / LayoutAssessment | 수행 검사와 범위/상태 / 원래 종합 판정·사유 | Checked/normal bool 하나로 합치면 미수행·실패·기준 이탈을 잃음 |
| ResultOperatorReview | productId+resultId가 해석하는 정확한 불변 결과, 확인 시점, 선택 확인자 기록 | OperatorReview는 기존 후보로 유지 가능. ProductApproval은 제품 영구 승인/제작 인증으로 오해 |
| StoredLayoutConsistencyIssues / SaveReadiness | 내용 불일치 진단 / 현재 전체 저장 판단 | canSave 저장 필드나 Result 패키지 도입을 뜻하지 않음 |

추천 결과 식별 범위는 문서 내 결과 ID 유일성이다. resultId 하나가 productId 하나와 불변 전체 결과를 정한다.
영역 결과는 제품 결과 아래 areaId로 연결하고 줄은 그 영역 목록의 순서로 식별한다.
줄마다 영구 UUID나 영역별 별도 확인 ID를 미리 만들지 않는다.
영역/줄 식별이 필요한 편집 명령이 생기면 최소 식별 계약을 다시 검토한다.

### 결과 작성 경위와 환경

엔진 생성 결과는 실제 생성 환경을 기록한다. 사용자 편집은 새 결과이며 실제 편집 경위를 기록한다.
기초 결과의 엔진 정보를 '편집한 결과를 그 엔진이 그대로 생성했다'는 의미로 바꾸지 않는다.
원본 결과 ID/환경을 선택 출처로 남길 수 있지만 영구 변경 이력 전체를 보관할 의무는 만들지 않는다.
직접 작성한 결과에 가짜 엔진 이름을 붙이지 않는다. 엔진 생성/사용자 편집의 구체 타입 표현은 후속 결정이다.
검사 도구/검사 기준의 식별은 생성 엔진과 구분한다. 사용한 내용/범위와 원래 사유를 보존한다.
운영 모델에 synthetic 여부 필드는 추가하지 않는다. 합성 자료의 구분은 시험 경로/예제 설명 책임이다.

## 5. 저장 결과의 최소 내용과 원문 대응

제품 완료 결과에는 정의된 각 영역의 현재 결과가 정확히 하나씩 있어야 한다.
하나의 영역만 성공한 상태는 메모리에서 그 영역의 재사용 후보로 보존할 수 있으나 제품 완료/전체 저장 성공은 아니다.
실패·계산 불가·탐색 미완료는 완료 영역 결과의 가짜 좌표/빈 줄/정상 판정으로 표현하지 않는다.
독립 영역을 유지해도 제품 전체 결과가 새로 구성되면 새 resultId이며 이전 제품 결과 확인은 승계하지 않는다.

| 결과 값 | 첫 표현 추천/불변식 | 아직 필요한 결정 |
|---|---|---|
| 원문 대응 | 영역별 순서 있는 줄 조각으로 원문 전체를 손실 없이 분할. 연결 결과가 sourceText와 정확히 같음 | 글리프/문자별 위치 표현이 필요한 최초 범위 |
| 직접 지정 줄 | 결과의 줄 분할이 입력 lines와 순서/내용까지 일치. 한 줄도 그대로 | 입력 제약 자체 변경은 별도 명령 |
| 자동 줄 | 실제 산출 줄 분할을 저장. 자동 입력이므로 열 때 다시 줄을 고르지 않음 | 자동 산출 알고리즘/그룹 정책 미구현 |
| 좌표/단위 | 기존 DrawingCoordinateSpace와 같은 설계 기준점·X 오른쪽/Y 위쪽. 길이 값은 그 문맥 단위를 따름 | 줄 기준점을 baseline 시작 등 무엇으로 할지 고정 필요. 화면/출력 변환은 외부 책임 |
| 글자 크기 | 같은 영역의 공통 실제 크기, 유한한 양수. 폰트 em/실제 글리프 높이 구분 | 이 '크기'의 측정 의미·텍스트 렌더링 계약 |
| 자폭 | 줄별 실제 유한 양수 비율. 예: 1.0의 기준을 명시한 무차원 값 | 압축/확대 허용 범위는 규칙 판정. 임의로 0~1에 제한하지 않음 |
| 글꼴 | 실제 사용 자원/스타일/특성과 측정 근거의 해석 가능한 연결 | 글꼴 임베딩/윤곽 보관·라이선스/렌더링 재현 방법 미정 |
| 기타 배치 | 실제 사용한 정렬/방향/추가 간격 등 해석에 필요한 값만 명시 | 회전·혼합 글꼴·문자별 조정은 지원 시 별도 설계. 누락을 0/기본 글꼴로 보정하지 않음 |
| 검사·사유 | 결과에 실제 수행한 조건과 통과/기준 이탈/실패/미수행/비적용을 구분 | 필수 검사 목록·허용 편차 세부 정책 |

배치 결과에 필요 없는 CAD 절대 좌표나 특정 원형 홀 전용 필드를 만들지 않는다.
기하 표현 성공은 엔진이 그 영역을 계산/검사할 수 있다는 뜻이 아니다. 미지원 경계를 외접 직사각형으로 대체하지 않는다.

### 문자 위치 후보와 최소 추천

| 단위 | 장점 | 주의 |
|---|---|---|
| UTF-16 코드 단위 | Dart String의 length/substring과 직접 대응 | surrogate pair 중간을 숫자 경계로 쓸 수 있어 별도 방어 필요 |
| Unicode 코드 포인트 | surrogate pair를 하나로 취급 | 결합 문자/ZWJ 이모지는 여러 포인트이며 사용자 인식 문자와 다름 |
| 확장 grapheme cluster | 편집 UI의 사용자 인식 문자에 가깝다 | 분할 규칙/Unicode 버전을 정해야 하며 원문 코드 단위 위치 변환 필요 |

**최초 결과 줄 대응은 원문 줄 조각 목록과 정확한 순차 연결만으로 시작하는 것을 추천한다.**
원문의 indexOf로 같은 문자열을 찾지 않고 누적 길이로 대응한다. 반복 문구/공백/Unicode 표현을 보존한다.
문자별 위치가 아직 필요 없다면 offset 필드와 줄 텍스트를 중복 정본으로 저장하지 않는다.
이는 Input의 SpecifiedLineBreak를 자동 결과 타입으로 재사용하라는 뜻이 아니다. 입력 제약과 산출 줄은 다른 책임이다.

후속 위치가 필요하면 UTF-16 코드 단위의 [start, end) 범위를 명시하는 후보를 우선 검토한다.
0 ≤ start ≤ end ≤ sourceText.length, 순서·빈 구간 허용 범위·겹침/누락, substring 일치를 검사하고
surrogate pair 중간 경계는 유효 문자 경계로 수락하지 않는 방향을 추천한다.
이는 후속 결과의 문자 경계 지원 제안이다. 기존 입력에서 surrogate pair/결합열을 가른 조각이 들어오면
후속 결과 지원 범위에서 어떻게 안내할지 별도 검토한다. 이번 근거 구현은 surrogate pair/grapheme 경계를 검사하거나 입력 허용 조건을 변경하지 않는다.

결합 문자·ZWJ/국기·한글 자모의 grapheme 중간 줄 경계까지 거부할지, 수동 조작에서 어떻게 안내할지는 미정이다.
숫자 위치가 유효하다는 사실과 실제 줄바꿈이 언어/글리프 단위로 적절하다는 판단을 구분한다.
불완전 surrogate 문자열의 저장/측정 지원도 후속 문자 정책에서 결정하며 임의 정규화하지 않는다.

기술 근거 확인(2026-11-01): [Dart String](https://api.dart.dev/dart-core/String-class.html),
[Unicode UAX #29](https://www.unicode.org/reports/tr29/)의 텍스트 분할 개념을 대조했다.
최신 Unicode 버전을 이 문서에서 채택하거나 새 분할 라이브러리를 설치한 것은 아니다.

### 복원·렌더링·재계산은 별개

저장 구조/참조/원문 연결/수치의 정합성을 해석하는 것은 과거 엔진 실행이나 충돌 검사를 재실행하는 일이 아니다.
과거 엔진/글꼴이 현재 없어도 이해 가능한 저장 결과와 원래 환경 식별은 복원할 수 있어야 한다.
동일 모습의 렌더링은 실제 글꼴/측정/셰이핑·렌더러가, 재계산은 지원 엔진·규칙·탐색 환경이 따로 필요하다.
불가능하면 그 기능의 지원 상태를 설명하며 대체 글꼴/현재 엔진 버전으로 저장 식별을 덮거나 자동 재계산하지 않는다.

## 6. 검사와 작업자 확인

검사 범위와 판정은 결과의 불변 내용이다. 사용자 편집 후에는 이전 검사 통과를 새 배치에 그대로 붙이지 않는다.
필요한 검사를 실제 새 결과에 수행한 뒤 판정/사유를 새로 연결해야 한다.

| 범위 | 처리 원칙 | 확정/미정 |
|---|---|---|
| 원문 손실/중복·지정 줄 위반·존재하지 않는 영역/불가능한 수치·참조 손상 | 확인으로 데이터 오류를 허용하지 않음 | 기존 값/저장 정합성 요구 |
| 홀 회피·허용 경계·원문 보존 등 기존 필수 조건 | 실제 위반을 확인으로 정상화하지 않음 | 기존 합의. 현재 구현이 검사한다는 뜻은 아님 |
| 자동 기준 이탈이지만 검토 후 저장 가능한 완료 결과 | 원래 판정/사유 유지 + 정확한 해당 결과 확인 | 저장 가능 방향은 확정. 어떤 편차가 이 범위인지 상세 목록은 결정 필요 |
| 저장 수락에 필요하다고 정한 검사 미수행/지원 불가 | 완료 판정으로 승격하지 않음. 검토만으로 검사 통과를 만들지 않음 | 필수 검사/버전별 지원 표부터 결정 |
| 실제 자재/설비·현장 공정 등 앱 검사 밖 항목 | '검사 안 함/범위 밖'을 보존. 이 소프트웨어의 완료를 제작 인증으로 표현하지 않음 | 새로 모든 현장 항목을 저장 차단 조건으로 만들지 않음 |

커터/최소 크기/자폭 등 개별 편차를 전부 허용 또는 전부 금지로 이번에 단정하지 않는다.
선택 가능한 자동 권장 기준과 반드시 지켜야 할 제작 제약을 첫 공정 지원 정책에서 구분해야 한다.
단순 '수동 결과니까 경고'나 '확인했으니 normal' 규칙을 두지 않는다.

확인 추천 최소 기록은 productId·resultId가 가리키는 정확한 불변 결과, 확인 시각, 선택적 확인자 표시 정보다.
확인자 정보가 없다는 뜻은 명시적으로 구분하고 서버 계정/전자서명/강제 로그인은 요구하지 않는다.
시각의 직렬화는 UTC 후보이며 시스템 시각/표시 이름만으로 실제 사람·신원·권한·부인 방지를 증명하지 못한다.
코멘트/서명/승인 절차는 필요 근거 없이 필수 추가하지 않는다.

같은 ID의 다른 결과 내용을 로드/교체하면 손상/충돌이다. resultId만으로 확인을 수락하지 않는다.
확인은 문서의 유일한 불변 결과 객체를 참조하며, 내용 변경은 새 ID·새 검사를 요구한다.
원본/새 구성을 대조할 때 같은 결과 ID→전체 내용 불변을 확인한다. 과거 제거 ID의 전역 이력까지 추적하는 것은 별도다.
저장 파일 자체의 입력·결과·확인을 함께 위조한 경우를 인증하는 서명 시스템은 이번 책임이 아니다.

## 7. 현재성: 내용 정합성과 실행 수명

두 층을 모두 구분해야 한다.

1. **저장 내용의 정합성:** 현재 제품에서 해석한 실제 계산 내용과 저장 근거/결과/확인을 대조한다.
2. **실행 중 수락:** 해당 활성 세션과 현재 관련 입력 세대에서 채택한 결과만 현재로 연결한다.
   준비 요청/계산 요청 시 기준을 캡처하며 사후 최신 토큰을 붙이지 않는다.

후속 전체 작업 소유자가 관련 영역/그룹의 입력 세대를 관리한다. 앱과 별도 카운터를 중복 관리하지 않는다.
작은 ProductDesignEditSession.revision은 구성 편집 기준이므로 그대로 모든 배치 입력 세대 대신 쓰지 않는다.
메타데이터 변경에도 그 개정은 달라질 수 있고, 반대로 아직 없는 규칙/측정/결과 변경은 현재 구성에 포함되지 않는다.
결과 현재성 bool/세션 토큰/진행 요청/실행 입력 세대는 파일의 영구 저장값으로 복원하지 않는다.

A→B→A로 관련 입력이 바뀌면 새 실행 세대다. 과거 A 결과·확인은 내용이 같아졌다고 자동 현재로 돌아오지 않는다.
명시적인 재계산/검증된 재사용 채택 경계가 필요하며 구체 재사용 기능은 후속이다.
수량/표시/출처만 바뀌면 배치 입력 세대가 바뀌었다고 간주하지 않는다.

재열기는 다른 경로다. 지원 완료 문서의 저장 정합성을 검증한 뒤 새 실행 세션에서 저장 결과/확인을
초기 상태로 명시 복원한다. 이전 실행 요청을 재개하는 것이 아니며 재계산/재확인을 무조건 요구하지 않는다.
이전 세션의 늦은 계산/확인 콜백은 새 세션에 적용할 수 없다.

## 8. 영향 범위와 무효화

| 변경 | 결과 처리 | 확인 처리 |
|---|---|---|
| 한 영역의 원문·입력 방식·지정 줄 | 해당 영역과 실제 의존 영역을 무효화. 제품 완료 연결 해제 | 기존 제품 결과 확인은 현재 적용 불가 |
| 한 영역 형상/명시 제외·관련 홀/규칙·측정 | 실제 영향을 받는 영역과 그룹 의존 대상. 독립 영역은 보존 가능 | 변경 후 제품 결과는 새 ID, 새 확인 판단 |
| 제품 추가/삭제·자동 그룹 이동 | 변경 전/후 참여 집합 및 의존 입력의 차이를 검토. 이전/새 그룹에 실제 영향 받는 영역 | 달라진 제품 결과에 대한 확인 해제 |
| 자동→직접 지정 | 해당 영역 새 입력. 그 영역을 자동 그룹에서 제외하고 이전 그룹의 남은 구성 재검토 | 영향 결과만 해제 |
| 직접 지정→자동 | 새 자동 그룹 참여 및 관련 입력 검토 | 영향 결과만 해제 |
| 직접 지정 영역 수정 | 지정 줄 보존 의도와 실제 입력 변경을 구분. 자동 패턴 등록/다른 자동 항목 기준으로 전파하지 않음 | 해당/실제 의존 결과만 해제 |
| 수량·출력 표현·제품 출력 순서 | 문구 배치 유지. 출력 구성만 변경 | 동일 결과 확인 유지 |
| 표시명·영역 label·순수 출처 기록 | 실제 계산 투영이 같으면 유지. 현행 스냅샷 ID 불변 조건은 별도 준수 | 결과 내용이 같으면 유지 |
| 실제 계산 규칙/글꼴 자원·엔진 선택 변경 | 명시 채택한 범위의 입력 세대 변경. 영향을 받는 결과 무효화 | 해당 결과 확인 재사용 불가 |
| 단위/수치 표현을 바꾸는 환산 | 비교/결과 좌표 표현을 명시 처리. '물리 크기 같음'으로 자동 유지하지 않음 | 새 결과 내용이면 승계 불가 |
| 사용자 결과 위치/크기/줄 배치 편집 | 새 불변 결과 및 그 결과의 검사. 과거 검사 재사용 금지 | 이전 결과 확인 승계 불가 |
| A→B→A 입력 복귀 | 과거 결과 자동 재채택 금지 | 과거 확인 자동 복구 금지 |
| 지원 완료 문서 재열기 | 저장 내용/근거 대조 후 새 세션 초기 상태로 복원 | 정확한 저장 결과의 확인 복원 가능 |

그룹 구성원은 productId+areaId와 관련 입력으로 식별한다. 같은 문구·도안·label로 자동 동일시하지 않는다.
직접 지정 본문은 공동 자동 줄바꿈 선택에서 제외하되 다른 실제 계산 의존성이 있다면 그 의존은 별도 기록한다.
삭제된 옛 의존 목록만 보고 새 구성원의 영향을 놓치지 않는다.
어떤 그룹인지 판별하는 알고리즘이 아직 없다는 이유로 모든 자동 제품을 영구적으로 한 그룹으로 확정하지 않는다.
지원하지 않는 의존 판별은 '확인 불가/재계산 필요'로 구분하고 정상으로 수락하지 않는다.

저장 읽기에서 확인 가능한 것은 참조 해석·저장 참여자/실제 입력·정책 내용의 내부 정합성이다.
현재 그룹 정책을 해석할 검증기가 없다면 새 구성원의 의미상 참여 여부까지 검증했다고 주장하지 않는다.
저장 기록을 해석해 복원하는 것과 변경 후 공동 결과를 현재로 채택/다시 저장할 수 있는 것은 구분한다.
생성 엔진이 설치되지 않은 것 자체와, 저장 정책/의존 의미를 해석할 수 없는 것은 다른 사유다.

## 9. 저장 판단 표

아래 판단은 전체 문서/필수 검사 정책이 준비된 뒤 수행할 후속 순수 검증의 목표다.
현재 구성의 빈 제품 목록 허용은 빈 작업 파일 저장 허용이 아니다. 빈 문서 정책은 미정이다.

| 상태 | 제품의 현재 완료 상태/확인 | 작업 파일 저장 판단 |
|---|---|---|
| 현재 입력의 정상 완료 결과 | 필요한 검사가 완료되고 판정/사유 유효. 별도 확인 불필요 | 다른 모든 제품도 조건 충족 시 가능 |
| 현재 입력의 검토 허용 기준 이탈 + 정확한 결과 확인 | 원래 판정/사유 유지 | 다른 모든 제품도 조건 충족 시 가능 |
| 같은 결과이나 필요한 확인 없음 | 결과는 있으나 review 필요 | 미완료/확인 필요. 파일 전체 보류 |
| 과거 입력의 결과 | 현재 근거와 다름 | 오래된 결과로 보류. 확인이 있어도 불가 |
| 결과 없음/계산 불가/탐색 미완료 | 완료 결과 없음 | 보류. 확인으로 대체 불가 |
| 여러 영역 중 일부 완료 | 독립 영역 재사용 후보는 가능, 제품 완료는 아님 | 보류. 일부 제품/영역만 저장하는 성공 없음 |
| 수량만 변경 | 배치/확인 유지 | 수량의 별도 값 정책까지 유효하면 배치 재계산 없이 가능 |
| 관련 입력/자동 그룹 구성 변경 | 실제 영향 결과 무효화 | 새 현재 완료 결과·필요 확인 전 보류 |
| 입력 A→B→A | 같은 값이라도 실행 현재 연결 해제 상태 | 명시 재수락 없이 과거 결과/확인으로 저장 불가 |
| 결과가 바뀌었는데 이전 확인이 남음 | 다른 결과 확인. 같은 ID 다른 내용이면 손상 | 확인 필요 또는 손상 진단. 자동 연결 금지 |
| 과거 엔진/폰트 미설치로 재열기 | 해석 가능한 저장 결과/근거/확인 자체는 복원 | 단순 미설치만으로 무효화하지 않음. 동일 렌더링/재계산 지원은 별도 |
| 필수 검사 미수행/정책 의미 미지원 | 완료 수락 여부를 판단할 근거 부족 | 정상/확인 가능 편차로 보정하지 않고 보류 |

이 표가 파일 생성/원자 저장/Drive 동기화·출고 완료를 보장하지 않는다.
서로 다른 작업 파일의 결과/확인을 발주 전체와 함께 무효화하거나 저장하지 않는다.

## 10. 실패·진단과 처리 경계

정상적인 결과 없음/부분 완료/확인 필요/오래됨은 편집 상태의 저장 보류 진단이다.
값/참조가 손상된 문서를 유효 객체로 만드는 것은 거부한다. API 오용/결함은 별도 예외다.

| 후보 사유 | 발생 조건 | 필수 상세/위치 방향·호출자 대응 |
|---|---|---|
| inputBasisMismatch | 현재 계산 투영과 결과의 실제 입력 근거가 다름 | productId, resultId, 근거 참조, 달라진 계산 필드 경로. 영향 입력 재계산/명시 재수락 |
| missingCompletedResult / incompleteAreas | 제품 결과 없음 또는 필요한 영역 일부 미완료 | 제품 ID·필요 areaId·각 상태. 결과 배열의 가짜 누락 슬롯 경로를 만들지 않음 |
| reviewRequired | 검토 허용 편차이나 정확한 결과 확인 없음 | 제품/결과 ID·편차 코드. 별도 정상 판단으로 확인 안내 |
| reviewTargetMismatch | 다른 제품/결과 확인 또는 현재 결과와 내용이 다름 | 확인의 참조 위치·기대/실제 제품/결과 ID. 필요한 확인을 새로 받음 |
| conflictingResultIdentity | 같은 ID 선언/전후 내용이 다름 | 첫/충돌 선언 인덱스·실제 바뀐 필드 경로. ID만 믿지 말고 문서/호출 수정 |
| invalidLineCorrespondence | 원문 손실/중복·줄 순서/지정 줄 불일치 | areaId·줄 0 기반 인덱스·길이/경계 단위/문제 구간. 원문 전체 없이 전달 |
| invalidPlacementValue | 비유한 수치·불가능한 참조/단위 문맥 등 | 실제 필드·연산·기대 범위/실제 수치. 값 복원 거부 |
| requiredInspectionUnavailable | 필요한 검사 미수행/미지원 | 검사 종류·실제 상태·필요 정책 식별/지원 범위. 확인으로 통과시키지 않음 |
| dependencyScopeUnverifiable | 그룹/규칙 의존 의미를 해석할 수 없음 | 정책 식별·관련 참여 ID·검사 한계. 새 현재 결과로 추정하지 않음 |
| duplicate/missing/unknown reference | 제품·영역·근거·결과 참조가 중복/부재/모호 | 관련 ID·0 기반 첫/중복/참조 위치. 하위 기존 code/fieldPath/details 보존 |
| unexpected type / unsupported representation | 타입 또는 지원 표현 불일치 | 기대/실제 타입 또는 실제 값·지원 범위. 기본값으로 복원하지 않음 |

필드 위치는 확정된 JSON 루트가 아니라 해당 검증 입력의 실제 모델 위치를 기준으로 한다.
예: ProductLayoutResult 후보의 `areas[1].lines[2]`, `inputBasis`, 확인 후보의 `resultId`.
아직 없는 WorkDocument.products[i].layout 같은 전체 저장 경로를 확정하지 않는다.
상위 조립 시 실제 입력/목록의 접두를 붙이고 하위 원래 경로·코드·상세·원인/최초 스택은 유지한다.
누락은 존재하는 제품/영역 정의 위치를, 잘못된 참조는 해당 참조 필드를 가리킨다.

독립 진단은 함께 수집하되 모호한 참조에서 파생된 가짜 누락을 중복 보고하지 않는다. 순서는 계약으로 고정하지 않는다.
진단 생성자의 잘못된 code/detail 조합은 런타임에서 인자명·값·조건을 가진 ArgumentError로 방어한다.
유효 값 생성/복원 거부와 저장 보류 결과는 다른 책임이다. Error를 catch해 보류/정상으로 바꾸지 않는다.

workflow 순수 검증은 로깅하지 않는다. 앱이 정상 보류/확인을 안내하고 예상 밖 실패를 기존 최종 경계에서 한 번 기록한다.
원문·전체 결과/입력·문서·Provider 상태를 진단/로그에 덤프하지 않는다. 필요한 실제 ID/위치는 구조화하되
파일 로그에 자동 포함하지 않고 기존 승인된 필드만 선택한다. toString 파싱/임의 Map 상세를 사용하지 않는다.

## 11. 합성 관계 사례와 후속 검증

**아래는 계약 검토용 합성 관계이며 실제 엔진 계산/홀 회피/제작 성공 사례가 아니다.**
좌표나 가짜 정상 결과를 채워 넣은 완성 JSON 대신 관계만 보여 준다.

| 사례 | 관계와 기대 |
|---|---|
| 지정 한 줄 + 엔진 정상 맞춤 | 입력 specified → 엔진 생성 → 정상 완료/필수 검사 충족 → 추가 확인 불필요. 원문/지정 상태 유지 |
| 자동 입력 + 사용자 배치 수정 | 새 결과 R2, R1의 판정/확인 재사용 금지. R2 실제 검사 후 허용 편차라면 R2 확인을 요구 |
| 수량 1→10 | 같은 입력 근거/결과 R1/확인 V1 유지. 출력 구성만 변경 |
| 원문 A→B→A | 저장 근거 값은 다시 같을 수 있으나 과거 R1/V1이 현재 연결로 자동 돌아오지 않음 |
| 저장 완료 R1/V1 재열기 | 지원 내용/참조 검증 후 새 세션 초기 상태에 R1/V1 복원. 이전 실행 토큰 복원/재계산 없음 |
| label·공용 출처만 변경 | 새 적용 스냅샷이 필요할 수 있으나 계산 투영이 같으면 그 이유만으로 R1 재계산하지 않음 |
| 두 영역 중 하나 실패 | 완료 영역은 보존 가능. 제품/파일 저장 완료 아님 |
| 자동 그룹에 새 참여자 추가 | 자신 입력이 같아도 공동 선택 의존 결과는 영향 검토. 새 참여자를 옛 의존 목록만으로 놓치지 않음 |

후속 시험은 고정 기대 값·진단 코드/경로/필수 상세를 비교하고 왕복끼리만 비교하지 않는다.
- 현재 값에서 별도 생성한 동등 입력, 원문 공백/결합 문자/이모지/반복 문자열·지정 한 줄/여러 줄 보존.
- 형상/영역/규칙/측정/그룹 변경 감지와 수량/출처/표시만 변경 시 배치 근거 유지.
- 결과 수정 후 새 ID/새 검사·과거 확인 차단, 같은 ID 다른 내용 거부, 독립 영역 보존과 제품 완료 재조립.
- 입력 세대 A→B→A, 이전 세션 늦은 결과 거부와 완료 저장 문서 재열기의 명시 복원 구분.
- 필수 검사/범위 밖 검사 구분, 정상 보류와 손상/오용 분리, 방어 복사·외부 목록/반환 JSON 변경 방어.
- 원문 줄 조각의 순차 대응, surrogate 중간 경계, 위치 단위/범위와 실제 추출 값.
- 추후 런타임 방어는 assert 비활성 AOT·생성기 없는 소비자로 확인. 실제 생성/분석/테스트와 엔진 실기는 구분.

## 12. 다음 한 번의 최소 구현 추천

**추천 범위 하나: 현재 구현된 형상·문구만을 위한 불변 ProductGeometryTextBasis와 좁은 내용 대조.**
완전한 ProductLayoutInputBasis/결과/저장 가능 판정부터 한꺼번에 구현하지 않는다.

| 추천 모델/후보 이름 | 현재 타입으로 담을 수 있는 값/근거 |
|---|---|
| ProductGeometryTextBasis | productId, DrawingCoordinateSpace, 실제 outline, CutoutDefinition 목록, 영역별 기하/문구 결합 목록 |
| AreaGeometryTextBasis | TextRegion + TextAreaInput. areaId는 input에서 파생하여 중복 정본을 만들지 않음 |
| capture/compare 함수 후보 | 유효 ProductDesignConfiguration에서 productId로 참조를 해석, 영역 ID로 결합하고 실제 값 차이를 구조화 진단으로 반환 |

대안 ProductLayoutInputSnapshot은 아직 없는 규칙/측정/그룹까지 완성됐다고 오해하기 쉽다.
GeometryText 이름은 보장하는 부분만 드러낸다. 이 타입에는 미정 조건의 null/빈 Map·가짜 EngineIdentity를 넣지 않는다.
문구 입력 타입·기하 타입·기존 참조 검증을 재사용하고 label/source/비대상 제품/수량은 계산 투영에 넣지 않는다.
불변 하위 값을 공유하고 외부 목록은 방어한다. JSON·문자 offset API·결과/확인·세션 연결은 이 첫 구현에 넣지 않는다.

검토 후 시작 조건은 이 좁은 투영의 비교 의미를 채택하는 것이다.
- 영역 입력/정의는 각각 areaId로 연결하며 같은 ID 집합과 영역별 내용이면 재정렬만으로 이 근거가 다르다고 하지 않는다. 원본 목록은 정렬/수정하지 않는다.
- outline 경로 구간과 경계 내부의 순서 있는 목록은 현재 값 의미를 보존한다.
  cutout/exclusion 순서를 실제 계산에서 무시해도 되는지 아직 증명하지 않고 임의 정렬/동등화하지 않는다.
- 적용 ID/출처와 계산 내용 비교를 구분하며 같은 ID의 내용 충돌은 기존 검증 책임을 유지한다.
- 제품 없음/참조 해석 실패와 값 차이 진단의 반환 형태·이름은 구현 전 검토한다. 비교 진단이 없다고 전체 배치 입력 일치/저장 가능이라 하지 않는다.

이 최소 부분은 현재 모델만으로 구현할 수 있다. 이후 전체 입력 근거를 만들려면 실제 규칙·제작 조건의 최초 범위,
측정/글꼴 자원, 그룹 의미·결과 줄/좌표 기준점·검사/허용 편차를 별도로 결정해야 한다.
그 선행 결정 전에는 결과/확인 전체 모델이나 저장 codec을 가짜로 완성하지 않는다.

## 13. 형상·문구 부분 근거 구현 (2026-11-01)

### 실제 공개 API

- `AreaGeometryTextBasis(definition:, input:)`: TextAreaDefinition과 TextAreaInput의 areaId를 대조하고
  region/input만 공유한다. areaId는 input에서 파생한다. label은 보관하지 않는다.
- `ProductGeometryTextBasis(productId:, coordinateSpace:, outline:, cutouts:, areas:)`:
  빈 제품 ID·소유 영역/관통 ID 중복을 거부한다. 목록은 방어하며 불변 하위 값은 공유한다.
- `extractProductGeometryTextBasis(configuration:, productId:)`: 유효 구성에서 해당 제품만 추출한다.
  새 전체 참조 검증 알고리즘을 만들지 않는다. 대상 없음은 GeometryTextBasisException.unknownProduct,
  빈 추출 인자는 ArgumentError.value(productId)로 구분한다.
- `compareProductGeometryTextBasis(previous:, next:)`: 수정 불가 부분 차이 목록을 반환한다.
  다른 제품은 productMismatch 하나만 반환한다. 빈 목록은 **이 부분의 일치**일 뿐 배치/현재성/저장 판정이 아니다.

GeometryText는 실제로 담은 부분만 드러내므로 후보 이름을 채택했다.
전체 규칙/측정/그룹을 갖춘 LayoutInput처럼 부르지 않는다. JSON·copyWith·임의 수정 경로를 제공하지 않으며
수정은 검증 생성자로 새 값을 만든다. 생성 도구는 값 비교/hashCode를 맡고 업무 연결 검사는 직접 작성한다.

영역의 유일 정본은 `areasById: Map<String, AreaGeometryTextBasis>`다.
이 맵은 명시 영역 ID별 소유 관계이며 임의 메타데이터 Map이 아니다. Freezed의 맵 값 동등성은 삽입 순서와 무관하다.
`areas`는 맵의 전달 순서로 파생한 수정 불가 목록이다. 다른 영역 순서의 근거라도 값/hashCode는 같을 수 있다.
진단 인덱스는 각 근거의 areas 관찰 순서를 각각 따른다. 입력 구성의 textInputs/textAreas는 정렬하지 않는다.

cutouts·TextRegion.exclusions·GeometryPath.segments·지정 lines는 순서까지 비교한다.
단위와 수치는 그대로 비교하며 자동 환산·허용오차·물리적 동등성 추정은 하지 않는다.
이 규약을 미래 엔진이 모든 순서에 무관하다는 보장으로 확대하지 않는다.

### 문자 경계의 두 문제

surrogate pair 중간은 한 코드 포인트의 UTF-16 표현 내부 경계다.
grapheme 중간은 결합 문자/ZWJ 등 여러 코드 포인트가 사용자 인식 문자를 이루는 경우의 경계다.
둘은 같지 않다. 결합 문자·ZWJ 등의 분할 허용 정책은 계속 미정이다.
이번에는 TextAreaInput을 그대로 공유한다. surrogate/grapheme 경계 검사·정규화·줄 재분할을 하지 않으며,
이미 허용되는 조각을 이 근거 생성 때문에 거부하지 않는다. 기존 지원 제한도 그대로다.

### 생성 오류와 차이 진단

생성/추출 오류는 GeometryTextBasisException과 전용 code/details다.
빈 ID, 대상 없음, 영역 정의/입력 불일치, 영역/관통 중복은 각각 구분한다.
진단 named 생성자가 코드/상세를 고정하고, 상세 ID/인덱스의 잘못된 인자는 ArgumentError.value로 거부한다.
내부 helper는 공개 진입점에서 export하지 않는다.

차이는 GeometryTextBasisDifferenceCode의 productMismatch/valueChanged/kindChanged/elementAdded/elementRemoved다.
작은 position 타입 ComparedBasisFields/AddedBasisElement/RemovedBasisElement/ChangedBasisKinds가
이전/다음의 실제 상대 필드 경로와 종류 변경의 실제 종류를 제공한다.
원문/전체 형상/구성을 상세에 복제하거나 문자열로 덤프하지 않는다. 진단 순서는 계약이 아니다.

예: 같은 영역 a가 이전 areas[0], 다음 areas[2]에 있고 원문이 바뀌었다면:

```text
code=valueChanged, previousProductId=p, nextProductId=p, areaId=a
position.previousFieldPath=areas[0].input.sourceText
position.nextFieldPath=areas[2].input.sourceText
```

영역 삭제는 이전 `areas[i]`만, 추가는 다음 `areas[j]`만 가리킨다.
원→경로는 outline 전체, 선분→원호는 해당 segments[i] 전체를 kindChanged로 가리켜
한쪽에 없는 radius/bulge 하위 필드가 존재한다고 표시하지 않는다.
경로 생성자는 현재 근거 필드 문법/영역 ID 필요 여부/상세 조합을 방어하지만,
외부에서 전달한 진단의 인덱스가 어느 실제 객체 범위에 드는지는 그 객체 없이 검증하지 못한다.
대조 함수가 자신이 받은 실제 두 값의 위치를 계산한다.

### 파일과 보장 범위

운영 파일은 lib/src/product/ 아래 area_geometry_text_basis.dart, product_geometry_text_basis.dart,
geometry_text_basis_extraction.dart, geometry_text_basis_comparison.dart, geometry_text_basis_errors.dart,
geometry_text_basis_differences.dart와 공식 생성 .freezed.dart 2개다.
책임별 테스트는 test/product의 해당 모델·추출·대조·진단 파일이며 준비 코드만 test/support에서 공유한다.

같은 적용 ID의 전체 내용 불변 검사는 기존 API가 계속 소유한다. 이번 투영과 혼합하지 않았다.
규칙·측정·제작 조건·그룹·결과·확인·실행 무효화·저장·엔진·파일 I/O는 구현하지 않았다.
특히 순수 부분 값이 A→B→A로 다시 같아지는 것은 정상이며 실행 현재성이 복구됐다는 뜻이 아니다.

다음 한 가지는 **첫 지원 문구 계산의 글꼴/측정 근거와 글자 크기의 의미 계약 설계**다.
실제 결과의 크기가 em인지 글리프 높이인지, 같은 모습/재계산에 필요한 자료가 무엇인지 아직 없어
현재 근거에 이를 추가할 수 없다. 결과/확인/저장 전체를 다음 구현으로 자동 포함하지 않는다.
