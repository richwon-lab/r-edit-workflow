# 현재 계약과 외부 경계

영역별 원문·줄바꿈 입력의 공개 API와 JSON 조각은 아래 범위로 구현했다. 그 밖의 업무 흐름·전체 작업 파일 형식은 책임의 기준이며 아직 구현된 API가 아니다.
구현된 영역 입력 API를 제외한 필드·클래스·메서드 이름과 직렬화 상세는 후속 구현에서 정한다.

## 구현된 영역 입력 API와 첫 지원 제한

공개 진입점 lib/r_edit_workflow.dart는 TextAreaInput, LineBreakInput, AutomaticLineBreak, SpecifiedLineBreak, TextInputErrorCode, TextInputValidationException을 노출한다. 내부 구현은 lib/src/text_area_input.dart다. TextAreaInput은 areaId·sourceText·명시적 lineBreak를 모두 받아 유효한 불변 값만 생성한다. 원문과 직접 지정 줄은 새 객체 또는 생성된 copyWith에서 함께 검증해 교체하며 중간 불일치 값을 만들지 않는다. 부모와 구체 타입의 수정 경로는 모두 실제 생성자를 호출한다.

areaId는 빈 문자열을 거부하고 전달한 문자열을 그대로 보존한다. 원문도 trim·공백 합치기·Unicode 정규화를 하지 않는다. 직접 지정은 한 줄 이상이고 모든 조각의 연결이 원문과 정확히 같아야 한다. 한 줄도 specified를 유지한다. 입력 목록은 방어 복사한 수정 불가 값이며 JSON 출력도 분리된 목록을 반환한다.

빈 원문·빈 줄·원문 또는 줄 조각의 CR/LF는 첫 구현에서 미지원이며 서로 구분되는 오류 코드와 필드 경로로 반환한다. 공백만 있는 문자열·탭은 빈 값으로 바꾸지 않는다. 이 제한을 전체 제품 정책으로 확정하지 않는다. 값 검증은 배치·제작 가능 판정이 아니며 문자 오프셋 API도 없다.

JSON은 areaId:String, sourceText:String, lineBreak:{mode:automatic|specified, specified일 때 lines:List<String>} 구조다. 방식은 필수이고 누락·null/타입 오류·모르는 방식·줄 불일치를 구분한다. 알려지지 않은 필드도 거부하며 automatic의 lines를 조용히 버리지 않는다. TextInputValidationException의 code와 fieldPath로 첫 오류를 전달한다. fieldPath의 목록 인덱스는 문자 위치 단위가 아니다. JSON 문자열 문법은 dart:convert가 검사하고 모델은 디코딩된 객체를 검사한다.

Freezed의 생성된 값 비교·copyWith와 json_serializable의 JSON 필드 변환을 사용한다. 실제 생성자에서 런타임 업무 검증을 수행하고 code/fieldPath와 sealed 타입 구분을 제공한다. 전체 WorkDocument 스키마·미완료 파일 저장은 도입하지 않았다. 전체 오류 코드와 실행 예시는 [README](../README.md)에 기록한다.

## 책임

작업 파일·제품·텍스트 영역, 변경 영향과 결과 무효화, 계산 요청과 현재 입력에 맞는 결과 수락,
작업자 확인, 저장 가능 여부,저장·불러오기와 출력 연결을 소유할 예정이다.

작업 파일 전체가 저장 단위다. 모든 제품에 현재 입력에 맞는 완료 배치가 필요하며,
정상 판정은 추가 확인 없이, 규칙을 벗어난 배치는 해당 결과의 작업자 확인을 거쳐 저장한다.
확인이 판정이나 사유를 바꾸지는 않는다. 계산 미완료를 확인으로 대체하지 않는다.
저장 실패·취소 시 이전 저장 파일과 편집 내용을 보존하는 방향이다.

작업 파일 JSON은 이 패키지가 소유한다. 내부 파일은 UTF-8 JSON으로 시작한다는 기준만 있으며,
스키마·버전 값·이전 형식 변환은 아직 구현되지 않았다. 저장 형식 버전과 계산 엔진 식별 정보는 구분한다.
엔진 내부 객체를 그대로 직렬화하지 않는다. 열기만으로 재계산하거나 이전 프로세스 계산을 재개하지 않는다.

## 외부 경계

| 담당 | 경계 |
|---|---|
| Flutter 앱 | 화면·사용자 명령·파일 선택 등 플랫폼 연결, 폰트 측정 자료 제공 |
| r_edit_workflow | 업무 데이터·변경 영향·결과 수명 관리·저장 형식·외부 공개 API 연결과 값 변환 |
| 배치 엔진 | 줄바꿈·크기·자폭·위치·공간 검사·그룹 선택·진단 |
| DXF 패키지 | 완료된 배치와 형상·수량 표현을 반영한 출력 자료의 DXF 표현 |

의존 방향은 앱 → 업무 흐름 → 배치 엔진·DXF다. DXF 단계에서 다시 배치하지 않는다.
엔진과 DXF는 앱이나 작업 파일 저장 형식에 역으로 의존하지 않는다.
현재 외부 패키지 연결과 경계 인터페이스는 구현하지 않았다.

## 적용 도안·배치 기준과 결과 연결

작업 파일 안에서 여러 제품이 같은 불변 적용 도안을 참조할 수 있다. 도안에는 실제 외곽·치수·홀·텍스트 영역과 제작 적용값을 보존하고, 각 제품은 영역별 원문·줄바꿈 방식·수량을 갖는다. 영역 이름이나 문구·목록 위치로 식별하지 않는다.

한 제품의 도안을 바꾸면 새 적용 도안을 만들고 그 제품의 참조만 교체한다. 전체 변경도 적용 대상 제품 집합을 명시한다. 공유 참조를 제자리에서 수정해 변경을 전파하지 않으며, 치수 변경으로 홀·영역을 자동 비례 확대하지 않는다. 대응되는 직접 지정 줄 구성은 유지하고 크기·자폭·위치를 다시 맞춘다. 영역 삭제·교체의 입력 대응이 모호하면 조용히 문구를 버리지 않는다.

배치 규칙과 문구 패턴은 도안 형상·영역과 구분한다. 실제 결합 조건·적용 내용·출처를 결과의 계산 근거에 연결한다. 공용 원본 변경은 현재 작업에 자동 반영하지 않는다. 기본값·지정 없음·사용 안 함을 구분하고 원문 보존·홀 회피·허용 경계 같은 필수 조건을 선택 규칙으로 해제하지 않는다.

제품 추가·삭제·자동/직접 전환·그룹 이동은 변경 전/후의 참여자와 실제 계산 의존 영역을 검토한다. 이전 그룹의 남은 참여자와 새 그룹의 영향 대상도 무효화 범위에 포함한다. 직접 지정 영역을 다른 제품의 자동 줄바꿈 기준으로 사용하지 않는다. 수량·제품 순서·출력 표현만 바꾸면 배치와 결과별 작업자 확인을 유지한다. 세부 그룹 구성 알고리즘은 아직 미정이다.

계산 입력 ID는 자체 입력뿐 아니라 실제 공동 선택 참여자·관련 입력·폰트 측정·엔진·탐색 조건을 포함한 불변 내용에 대응해야 한다. ID 문자열 일치만으로 결과를 수락하지 않는다. 요청 수락 시 세션·요청·현재 입력/그룹과 캡처 내용을 대조한다. JSON 읽기에서도 참조·영역·원문 연결·지원 수치·판정/확인과 현재 입력 대 저장 스냅샷 내용을 검증한다. 같은 ID에 다른 내용이 연결되면 오류다.

열기 검증은 배치 알고리즘·최적성·글리프 공간 검사의 재실행이나 파일 진실성 증명이 아니다. 그룹 지원 검증기가 없는 읽기에서 의미상 새 참여자의 소속까지 검증했다고 주장하지 않는다. 재열기는 저장 결과를 보존하며 측정/엔진 지원 확인은 재계산과 구분한다.

합성 예제라는 구분은 문서·테스트 자료에서 관리한다. 운영 EngineIdentity에 합성 여부 필드나 이를 기준으로 한 저장 분기를 추가하지 않는다. 합성 왕복 시험과 실제 엔진 계산·제작 검증은 보고에서 구분한다.

이 절의 근거는 앱 논리 설계 2·3·5·6·10·11장과 기능 점검표 F13~F15/F27~F29/F31/F37, N08/D09/D12다. N08/D09/D12의 구현 초안·권장안과 구체 알고리즘 미정을 구분하며 상세 모델 이름은 확정 API가 아니다.

## 채택한 구현 도구와 소비 환경

2026-10-20부터 프로젝트 전용 Flutter 3.47.7/Dart 3.13.5를 사용하고 SDK 제약은 ^3.13.5다. Freezed 4.0.3/json_serializable 6.14.1의 필요한 생성 파일은 Git 관리 대상이며 소비자가 별도 생성 없이 사용하도록 유지한다. 업무 검증에는 assert만 사용하지 않는다. [전환·검증 기록](freezed-migration.md)과 [개발 기준](development-rules-draft.md)을 따른다. 현재 이름·JSON·오류는 [초기 정리 결정](input-naming-json.md)을 따른다. 초기 형식의 구형 지원·별칭·마이그레이션은 제공하지 않는다.


JSON 경계는 구조·필수·타입·지원 방식을 검사하고 생성자는 업무 조건을 검사한다. 루트 fromJson은 줄바꿈을 미리 생성하지 않으며 생성된 필드 변환에서 한 번 복원한다. 복수 오류의 발생 순서는 계약으로 보장하지 않는다. auto/manual은 unknownLineBreakMode로 거부한다.

## 적용 도안·영역의 첫 형상 제안

[설계 문서](applied-design-geometry.md)에 모델/필드/단위/불변식과 변경·검증 경계를 기록했다. mm·명판 왼쪽 아래 원점·직사각 외곽/영역·원형 홀은 첫 지원 제안이며 현재 구현 API가 아니다. 도안은 정의를, 제품은 원문/줄 입력을 소유하고 계산 요청에서 실제 영역·문구·규칙을 결합한다. 여러 제품의 불변 도안 공유와 개별 변경 시 새 참조·전체 변경의 명시 대상 집합 원칙을 유지한다.

영역과 홀의 겹침 자체는 거부 사유가 아니며 실제 글자의 홀 침범과 구분한다. 유한 수치/양수 치수 같은 값 검증, 도안/입력 참조와 중복 ID, 형상 포함/간섭, 엔진의 배치 판정은 서로 다른 책임이다. 도안 밖 형상·홀 간 접촉/간섭·영역 간 충돌 정책과 허용오차는 상세 설계의 제안/미정을 따른다. 반올림·기본값·지원 형상 보정으로 문제를 숨기지 않는다. 제작 조건 전체와 엔진/DXF 경계를 이번에 구현한 것은 아니다.
